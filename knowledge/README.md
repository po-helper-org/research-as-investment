# База знаний исследований

Здесь живёт всё, что исследования оставляют после себя и что пригодится следующим: факты, кросс-идейные выводы, отброшенные гипотезы, открытые вопросы и журнал окупаемости. Зачем это нужно и как пользоваться — в [методологии](../METHODOLOGY.md), шаги 2, 7 и 8.

| Файл | Что внутри | Когда пополнять |
| --- | --- | --- |
| [facts.jsonl](facts.jsonl) | Атомы: один факт с источником — одна строка | Каждый факт с источником, найденный в любом исследовании |
| [patterns.md](patterns.md) | Выводы, которые верны за пределами одной идеи | Когда факт или исследование меняет оценку целого класса идей |
| [graveyard.md](graveyard.md) | Отброшенные гипотезы с причиной и условием воскрешения | Каждое отсечение после L0 и глубже |
| [questions.md](questions.md) | Вопросы без ответа с ценностью и способом ответа | Каждый вопрос, который исследование не закрыло |
| [ledger.md](ledger.md) | Журнал окупаемости исследований | В конце каждого исследования |

## Формат атома

```json
{"fact_id": "F-2026-10-18-001", "claim": "Одна проверяемая фраза с цифрой и единицей", "as_of": "2025", "checked": "2026-10-18", "source": "[Название](https://...)", "evidence": "E1", "criteria": ["M"], "tags": ["b2c", "цифровые-книги", "ru"], "caveat": "Чем факт ограничен: кто считал, методология, расхождения", "used_by": ["my-idea-001"]}
```

| Поле | Правило |
| --- | --- |
| `fact_id` | `F-<дата добавления>-<номер>` (`F-ГГГГ-ММ-ДД-NNN`), уникален. Атомы, записанные до проверки формата, можно оставить с их id, перечислив id в `legacy-fact-ids.txt` рядом с `kb.py` (по одному в строке): список замораживается, новые атомы — только по шаблону |
| `claim` | Одна мысль своими словами; цифра с единицей и периодом. Два факта — две строки |
| `as_of` | На какую дату или период верен факт |
| `checked` | Когда проверен поиском; при перепроверке обновляется |
| `source` | Ссылка `[Название](URL)`; для E0 — слово «гипотеза» |
| `evidence` | Одна строка — уровень `E0`…`E6` из методологии. Пояснение к уровню — в `caveat`, не сюда |
| `criteria` | Список кодов критериев и стоп-критериев из `scoring/rubric.json`, на которые факт влияет; может быть пустым. Пояснения — в `caveat` |
| `tags` | Понятия, а не идеи: сегмент (`b2c`, `b2b`), отрасль, канал, регион, тип игрока. Строчными, через дефис |
| `caveat` | Обязателен, если источник заинтересован или источники расходятся |
| `used_by` | Список идей и досье, которые опирались на факт; дополняется при переиспользовании |

Если источники расходятся, это два атома с перекрёстной ссылкой в `caveat`, а не один с удобной цифрой.

## Команды

```bash
python knowledge/kb.py check        # проверить файл: каждая ошибка — «line N (fact_id): …», без падения на кривых типах
python knowledge/kb.py find b2c G   # факты, где есть все термины: тег, критерий или слово
python knowledge/kb.py stale 90     # факты, не перепроверявшиеся 90 дней
python knowledge/kb.py check --facts examples/deepstash-ru/facts.jsonl   # другой файл
```
